·開始之前

整個服務不自建伺服器、不自建資料庫：前端是純靜態網頁，後端是 Google Apps Script，資料庫就是一份 Google 試算表。你只需要準備：

一個 Google 帳號（拿來建 OAuth 憑證、Apps Script 後端、還有你自己的資料試算表）
一個 GitHub 帳號（放前端靜態網頁，用 GitHub Pages 發佈）
約 15 分鐘不被打斷的時間 —— 步驟 A～D 一次做完最順
✅ 目前狀態 試算表還沒建立。它不是手動在 Google 試算表首頁新增的，而是步驟 B 執行 setup() 時由程式自動建立 —— 順序不能跳過，Client ID 要先拿到才能填進 Code.gs。

A申請 Google OAuth Client ID

用來讓參與者「用 Google 帳號登入」。只取 Email 與顯示名稱，不需要審核就能給少數人測試用。

  1. 前往 Google Cloud Console → 建立新專案（名稱隨意，例如 jioka）
  2. 左側選單找「Google Auth Platform」（新版介面把「API 和服務 → OAuth 同意畫面」整合到這裡了）→「總覽」頁面點「開始」跑設定精靈
    · 應用程式資訊：名稱填「揪咖 JioKa」、支援 Email 選自己的
    · 目標對象：選「外部 External」
    · 聯絡資訊：填開發人員聯絡 Email → 完成建立
    · 完成後預設是「測試 Testing」狀態，只有你加入的測試使用者能登入 —— 要開放任何人登入見下方 步驟 E
  3. 左側選單「用戶端」→「建立 OAuth 用戶端」
    · 應用程式類型：網頁應用程式
    · 已授權的 JavaScript 來源加入：https://<你的帳號>.github.io（不要加結尾斜線）與（可選）http://localhost:8000
    · 已授權的重新導向 URI 不用填（本專案走 Google Identity Services 的 ID token 流程，不用 redirect）
  4. 建立後複製「用戶端 ID」，格式像 123456789-xxxx.apps.googleusercontent.com —— 步驟 B、C 都要用到

B建立 Apps Script 後端（含試算表）

這一步同時把「後端 API」跟「資料庫試算表」一起生出來 —— 試算表是 setup() 執行時自動建立的，不用另外手動開一份。

  1. 前往 Google Apps Script →「新專案」
  2. 把整份 gas/Code.gs 貼上、取代編輯器裡的預設內容
  3. 把檔案開頭的 Client ID 換成步驟 A 拿到的值： 
    const GOOGLE_CLIENT_ID = '123456789-xxxx.apps.googleusercontent.com';
  4. 建議：左側「專案設定」勾選「顯示 appsscript.json」，把 gas/appsscript.json 內容貼上覆蓋（設定台灣時區與最小權限範圍）
  5. 函式下拉選單選 setup → 按「執行」
    · 第一次執行會要求授權：選自己的帳號 →（若跳出「Google 尚未驗證這個應用程式」）點「進階」→「前往○○（不安全）」→「允許」，這是你自己的腳本呼叫你自己的試算表，正常現象
    · 執行成功後看「執行記錄」，會印出 ✅ 初始化完成！試算表網址：https://...
    · 這份試算表就是完整的資料庫（Events / Options / Votes / Comments / Participants 五張表），建議打開加書籤 —— 之後查原始資料、救回誤刪的活動都靠它
  6. 部署：右上角「部署」→「新增部署作業」
    · 類型選「網路應用程式」，執行身分「我（自己的帳號）」，誰可以存取「所有人」
    · 部署後複製「網路應用程式網址」（結尾是 /exec），步驟 C 要用
修改 Code.gs 之後前端沒反應？/exec 網址是「部署快照」，改完程式要回「管理部署作業」選「新版本」重新部署才會生效。
開發者注意：Sheet.appendRow() 就算欄位已鎖純文字格式，仍會自動把像日期的字串轉成 Date 物件（Range.setValues()/setValue() 才會正確遵守文字格式）。Code.gs 的 appendRow() 輔助函式已改用 setValues() 寫入，之後新增寫入邏輯請沿用這個 helper，不要直接呼叫 sh.appendRow()。

C設定前端

前端無框架、無建置流程，唯一要改的就是這個設定檔。

編輯 docs/config.js，填入兩個值：

const JIOKA_CONFIG = {
  API_URL: 'https://script.google.com/macros/s/AKfycb.../exec',   // 步驟 B 的網路應用程式網址
  GOOGLE_CLIENT_ID: '123456789-xxxx.apps.googleusercontent.com',   // 步驟 A 的 Client ID
  POLL_INTERVAL: 10000,
};

D部署到 GitHub Pages

  1. 把整個專案推到 GitHub（或用 GitHub Desktop 發佈）
  2. repo 頁面 →「Settings」→「Pages」：Source 選「Deploy from a branch」，Branch 選 main，資料夾選「/docs」→ Save
  3. 等 1～2 分鐘，開啟 https://<你的帳號>.github.io/jioka/（repo 名稱不是 jioka 的話路徑會不同）
如果實際網域跟步驟 A 填的不一樣（例如自訂網域），記得回 Cloud Console 把正確網域補進「已授權的 JavaScript 來源」，不然登入按鈕會失敗。

E發布正式版，讓任何人都能登入

可選步驟。步驟 A 建立的 OAuth 應用程式預設是「測試」狀態，只有你手動加入的測試使用者能登入；要把連結分享給朋友、任何人都能發起自己的揪咖，需要發布成正式版。

  1. Cloud Console →「Google Auth Platform」→「品牌」，把必填欄位補齊（沒填完「發布應用程式」按鈕會是灰的）
    · 應用程式首頁：填 GitHub Pages 網址，例如 https://<你的帳號>.github.io/jioka/
    · 應用程式隱私權政策連結、服務條款連結：沒有專門文件的話可以先填同一個首頁網址
    · 已授權網域：確認有 <你的帳號>.github.io
  2. 回「目標對象」頁面，「發布狀態」應該已經可以點「發布應用程式」→ 確認發布
  3. 發布狀態變成「實際運作中 In production」即完成；本工具只要求 email/profile 基本範圍，不需要送 Google 審核
之後任何人打開你的 GitHub Pages 網址，都能用自己的 Google 帳號登入、發起自己的揪咖活動 —— 資料一樣存進你的試算表，用 event_id 互相區隔，不會互相干擾。

✓驗收測試清單

部署完照著走一遍，確認整條鏈路通了再分享出去。

·三種身分怎麼用

誰是管理者不是設定出來的，是「誰先手」決定的：第一個對某場活動投票的人自動變主揪。

👑 主揪（發起人）
  1. 首頁「🎉 發起揪咖」→ 登入 → 填名稱、類型、說明、截止時間
  2. 月曆點日期 → 勾時段（可複選/自訂，例如「傍晚」）
  3. 填地點名稱 + Map 連結（可留空），可加多個
  4. 送出後把連結丟 LINE 群組（Modal 內建 LINE 分享）
  5. 管理後台可以：看明細、刪留言/選項、延長或提前結束投票、指定次管理者、標記最終方案、下載 CSV
  6. 「🔁 再揪一次」一鍵複製類型與地點清單開新場
🙋 參與者
  1. 打開連結 → Google 登入 → 設定本場暱稱（同場不能撞名）
  2. 點候選日期勾時段；點還不是候選的日期可「提議新日期」
  3. 地點點「我可以」（可複選），也能「新增候選地點」
  4. 下拉選對整場或特定選項留言
  5. 截止前隨時回來改都可以；截止後投票與留言鎖定，結果頁仍可查看
🤝 次管理者
  • 由主揪在後台輸入 Gmail 指定，對方用該帳號登入即自動生效
  • 能新增候選日期/地點、刪除留言、查看投票明細
  • 不能修改或刪除主揪已建立的選項與活動設定 —— 權限設計成「只能加、不能拆」

?常見問題

登入按鈕沒出現，或出現錯誤？

檢查 Cloud Console「已授權的 JavaScript 來源」是否包含你實際開啟的網域（https://xxx.github.io，注意大小寫與有無尾斜線）。前後端兩處的 Client ID 要填同一組。

任何人都能用我的揪咖嗎？

OAuth 同意畫面若是「測試」狀態，只有你加入的測試使用者能登入；要開放給任何人，照 步驟 E 發布成正式版即可，通常無需人工審核。

Google ID token 過期怎麼辦？

效期 1 小時，過期後操作會提示重新登入，再點一次登入按鈕即可，投票資料不會遺失。

資料會不會遺失？誰看得到？

所有資料存在你（部署者）帳號下的試算表，前端完全碰不到，只能透過 Apps Script API 存取。刪除活動/選項/留言都是軟刪除（標記不顯示），要復原可直接改試算表。

想用指令列管理 Apps Script？

可安裝 clasp：npm i -g clasp → clasp login → 在 gas/ 目錄 clasp create 或 clasp clone → clasp push 推送程式，方便版控。

🔒隱私與安全

  • 登入採 Google Identity Services，只取 Email 與顯示名稱，不索取其他權限、不存密碼
  • 前端拿到的 ID token 只存在記憶體與本機 localStorage（效期 1 小時）
  • 後端驗證 token 時比對 aud 是否為本專案 Client ID，防止他站 token 混用
  • 公開 API（getEvent）不回傳任何參與者 Email；Email 明細僅主/次管理者可見
